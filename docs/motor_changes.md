# 换成实际电机时要改的地方

现在电机型号还没定。代码里留的是 **M2006 + C610 的例子**，不是万能电调驱动。默认情况下电机服务是关的、电流限幅是 0、PID 全是 0。光改个型号名字是没用的。

## 要改的参数都在一个文件里

打开 [app_config.hpp](../threads/include/app_config.hpp)，搜 `// 改成实际电机`，要核对的有这些：

| 项目 | 要确认什么 |
| --- | --- |
| 硬件确认 | 电机/电调型号、供电、急停、固定好、协议对不对；没确认前保持 false |
| 总线和 ID | 用 CAN1 还是 CAN2、电调拨码 ID 是几、反馈 ID、会不会和别的设备撞 |
| 减速比 | 转子转速 ÷ 输出轴转速；别把输出轴 rpm 又除一遍 |
| 电流限幅 | 指令计数和实际安培怎么对应、电调能承受多少；这里填的不是安培 |
| 速度环 PID | 输入是输出轴 rad/s，输出是电流计数；先调 P 再调 I |
| 位置环 PID | 输入输出轴 rad，输出 rad/s；先把内环（速度）调稳再调外环 |
| 积分/速度限幅 | 外环最大速度、内外环积分上限 |
| 超时和周期 | 反馈周期、控制周期、命令刷新周期；断联立刻松开，重连不自动恢复 |

## 如果用的不是 M2006/C610

1. 在 [modules 层](../modules/) 改或加驱动：确认反馈帧格式、角度分辨率、正负方向、大小端、电流单位、使能/失能命令、故障状态。示例里的 `0x201..0x208`、`0x200/0x1FF`、8192 线编码器、±10000 指令只对这一套协议有效。
2. 在 [threads 层](../threads/) 换掉实例和注册方式，但保留松开、速度环、双环这些接口。别让具体电机协议混进 BSP 层。
3. 如果新协议用 CAN FD、扩展帧、UART 或者专用使能脚，得先补 BSP 的能力。注意 STM32F407 的片上 bxCAN **不支持 CAN FD**。
4. 波特率在 [board.ioc](../board/board.ioc) 里改完要重新生成；检查两端终端电阻、共地、CANH/L 有没有接对。
5. 集成测试要确认：重复 ID 会被拒绝；负数反馈和指令正常；编码器过零不错乱；断联/坏帧能处理；故障时输出归零。

## 上电顺序（别跳步）

先别接电机动力电源，只测通信 → 确认反馈的单位和方向对 → 固定好电机、设个小的电流限幅 → 先只开速度环 → 速度环稳了再开双环。每次切模式前松开电机、清掉积分。千万别一上电就自动转。

还有：就算总线断了，软件最多只能试着发个零帧，不能保证电调真收到。所以电调自己的通信超时保护和物理急停开关是必须要有的。
