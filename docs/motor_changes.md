# 换成实际电机时改哪里

当前型号未确定。代码保留 **M2006 + C610 示例协议**，不是通用电调驱动；默认关闭电机服务、未确认硬件、零电流限幅、零 PID。仅更改型号名称不能完成移植。

## 集中配置

在 [app_config.hpp](../threads/include/app_config.hpp) 搜索 `// 改成实际电机`：

| 项目 | 应核对/填写的内容 |
| --- | --- |
| 硬件确认 | 电机、电调型号、供电、急停、机械固定、通信协议；确认前保持 false |
| 总线与 ID | CAN1/CAN2、拨码/配置 ID、反馈 ID、是否和其他设备冲突 |
| 减速比 | 转子速度÷输出轴速度；不要把输出轴 rpm 再除一次 |
| 电流限幅 | 指令计数与安培的对应关系、电调额定值、机械安全上限；不是直接填安培 |
| 速度环 PID | 输入输出轴 rad/s，输出协议电流计数；先 P 后 I，记录采样周期 |
| 位置环 PID | 输入输出轴 rad，输出 rad/s；内环稳定后调外环 |
| 积分与速度限幅 | 外环最大输出速度、内外环积分上限，不只限制最终电流 |
| 超时与周期 | 反馈周期、控制周期、命令刷新周期；断联立即松开，重新连接不自动恢复 |

## 不是 M2006/C610 时

1. 在 [设备层](../modules/) 新增或修改驱动：确认反馈帧格式、角度分辨率、正负方向、大小端、电流/转矩单位、使能/失能命令和故障状态。示例中的 `0x201..0x208`、`0x200/0x1FF`、8192 线编码器、±10000 指令仅适用于所实现协议。
2. 在 [服务层](../threads/) 替换实例和注册方式，保留松开、速度环、位置-速度双环接口。不让具体电机协议进入 BSP。
3. 如协议使用 CAN FD、扩展帧、UART 或专用使能引脚，先补足 BSP 能力；STM32F407 的片上 bxCAN **不支持 CAN FD**。
4. CAN 波特率在 [board.ioc](../board/board.ioc) 修改后重新生成；检查两端终端电阻、共地、CAN H/L。GPIO、PWM、电源与电调匹配，不能仅靠软件推断。
5. 集成测试确认：重复 ID 拒绝注册；负数反馈和指令；编码器过零；断联/错误帧；停用/故障输出零；未注册槽位不误驱动其他电机。

## 上电顺序

先断开电机动力电源测通信 → 校验反馈单位与方向 → 固定电机、设置低电流限幅 → 只启速度环 → 速度环通过后启双环。切换模式前松开、清积分。最终通过构建开关启用 control 服务，再由带超时的命令接口显式请求模式与目标值；不要开机自动转动。

若总线断线或邮箱满，软件只能尝试发送零帧，不能保证电调收到；需要电调自身通信超时保护和物理急停。
