# I²C 笔记

## I²C 是咋回事

I²C 只用两根线：SCL（时钟）和 SDA（数据）。SDA 一根线又要发又要收，所以是半双工的，跟 SPI 那种收发分开的不一样。这两根线都是开漏的，要靠外部上拉电阻才能变高电平，不能直接把高电平硬推上去。

时钟由主机产生。有时候从机忙不过来，会把 SCL 拉住不放（叫 clock stretching），主机得等着。

时序上：SCL 高的时候 SDA 往下跳是 START，往上跳是 STOP；数据都是在 SCL 低的时候变、高的时候被读走。每发完 8 位，第 9 位是 ACK/NACK 应答。

读一个寄存器的完整流程一般是：

```
START → 发地址+写 → 发寄存器号 → 再来个 START → 发地址+读 → 收数据 → 最后回 NACK → STOP
```

注意 NACK 有两种意思：可能是那个设备根本不在，也可能是接收方说"我读完了"。要结合当时进行到哪一步来判断。

## 这块板子上的配置

- 用 I2C3：SCL PA8、SDA PC9，400 kHz，7 位地址，开漏加外部上拉。
- 这里 PCLK1 是 21 MHz，时序常数不能直接照抄别人 42 MHz 算好的，交给 CubeMX/HAL 按实际时钟配。
- 传地址给 BSP 时用没移位的 7 位地址，只在 HAL 那一层左移 1 位，别重复移。比如 IST8310 的 7 位地址是 0x0e，传给 HAL 就是 0x1c。
- IST8310 磁力计是选做的，目前只留了读写寄存器的接口，还没真的初始化读磁场。

## 上拉电阻不是随便接的

上拉太弱，总线充电慢，波形爬不上去；太强，低电平时灌的电流又大。大概估算 `tr ≈ 0.8473 × Rp × Cb`，400 kHz 快速模式要求上升时间不超过 300 ns。没实际量过电容和波形之前，别拍脑袋说某个阻值一定能用。

## 调试顺序

供电、共地、两根线空闲时为高 → 地址有没有 ACK → repeated START 和数据对不对 → 拔掉设备要能在有限时间内报错返回。不要一直死循环重试；如果 SDA 一直被拉低，要去想怎么复位恢复总线，而不是简单地把等待时间加长。
