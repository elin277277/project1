# 四层设计与验证顺序

目标是可替换板卡与设备，不是让一个电机协议适用所有电机。

| 层 | 位置 | 职责与边界 |
| --- | --- | --- |
| Board | `board/` | CubeMX 外设初始化、中断入口、链接脚本、板级资源绑定 |
| BSP | `bsp/` | HAL 适配；统一状态、超时、通信端口与回调；不解析电机/IMU 协议 |
| Module | `modules/` | 设备寄存器、通信协议、单位与状态；注入端口，不引用 HAL 或 RTOS |
| Service | `threads/` | 创建 ThreadX 对象、启动顺序、采样与控制周期、同步快照、心跳与故障处理 |

`libs/` 放独立 PID/CRC/数学算法。依赖由 Service 向下，BSP 不反向包含 Module；接收事件通过初始化时注册的回调通知上层。

## 端口与所有权

- 轻量端口采用 `context + 函数指针`，不分配堆内存。上下文、设备实例和异步缓冲区必须存活至停止服务。
- Module 构造函数只保存依赖，不访问外设。初始化必须在 Board/BSP 就绪后显式调用。
- SPI 一次片选期间包含地址、dummy 和数据；同总线只有一个服务拥有，未来增加多个设备时，必须对完整事务加锁，不能只锁单次字节交换。
- CAN ISR 只发布有界反馈；控制服务读取一致快照、计算控制并发送。未知 ID 不注册，不驱动。发送成功仅表示进入邮箱，不等于电调收到。
- UART 异步发送/接收明确缓冲区生命周期，忙时返回，不覆盖上一帧；DMA 中断和 UART 空闲中断都必须配置。
- IMU 读取失败不发布半帧，快照包含有效位、时间和错误。线程存活与设备健康分别表示。

## 安全默认

电机型号未知，驱动示例保留但服务默认不启动。启用服务也不等于允许运动：硬件确认、限幅、有效反馈、显式模式命令与未过期目标必须同时满足。模式切换/超时清积分，故障不自动恢复。完整替换项目见 [电机清单](motor_changes.md)。

## 逐层验收

1. **Board**：从空 IOC 配置并实际生成；只编译 Board。核对时钟和实际板级引脚，保留配置依据。
2. **BSP**：链接进 Board，验证参数/忙/错误返回、中断路由与 DMA 生命周期；硬件信号仍需实测。
3. **Module**：用主机假端口验证 PID、寄存器 dummy、负数与单位、CAN 报文与安全状态；再交叉编译。
4. **Service**：链接真实 ThreadX；检查向量、HAL tick 与 RTOS tick 分工、优先级、静态栈和同步。功能按开关逐一验证。

构建通过不代表电路连接正确；模拟测试不替代逻辑分析仪、CAN 分析仪、下载和带负载测试。
