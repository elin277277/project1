# 实板调试记录

这里是我在真板子上调试时踩的坑和怎么找到的，记给自己看的。工具是 ST-LINK/V2 + OpenOCD（用 telnet 连 50002 端口读寄存器）。

## 旧板子一直 HardFault，最后发现是板子坏了

**现象**：程序烧进去跑个十秒左右就卡死在 `HardFault_Handler` 里，而且每次卡的位置都不一样（有时候在 `tx_mutex_get`，有时候在 BMI088 的 `Config` 或 `Exchange`）。

**怎么查的**：

1. 先看 PC 停在哪 → 发现每次崩的地方都不一样。一般软件 bug 会在同一个地方崩，乱跳说明可能不是某一行代码的问题。
2. 读崩溃现场里那些坏掉的指针，发现全是 `0x20xxxxxx` 变成 `0x28xxxxxx`，就是固定多了 `0x08000000`（第 27 位被置成 1）。软件出错不会这么规律，开始怀疑硬件。
3. **最关键的一步**：复位之后先不运行，直接读那块内存 `0x20001808`，结果读出来就已经是坏的了（`0x28001954`）。程序一条指令都没跑，内存就是坏的 → 肯定是板子 SRAM 坏了，不是软件写坏的。

**结论**：这块板子 SRAM 在 `0x20001808` 附近有个位坏死了，软件救不了。换了一块板子马上就好了。

> 教训：崩溃位置乱跳 + 错误值很规律 + 复位后没跑就是坏的，这三条凑齐基本就是硬件问题。

## 新板子 BMI088 一切正常

- 没再 HardFault，CFSR=0。
- IMU 线程一直在跑，`sequence` 一直涨（3 秒涨了 900 多次）。
- 加速度 `(0.18, -0.01, 9.87)`，模长 9.87 差不多就是 1g；把板子翻过来，Z 轴从 +9.86 变 -9.68，方向对。静止时陀螺接近 0，温度 23°C 左右。
- 旧板上之前出现的"加速度 Y/Z 恒为 0"，其实也是那块板 SRAM 坏了把数据搞乱了，不是驱动写错。

## CAN 收不到电机反馈（还没解决）

**现象**：M2006+C610（ID 拨到 1，对应反馈 0x201）接好了，但是电机反馈数据全是 0。

**怎么查的**：

1. 先把 CAN 切成环回模式（自己发自己收，不经过外面的线）→ ESR=0 完全正常 → **说明 C 板的 CAN 外设本身是好的**，问题在外面。
2. 读错误寄存器 `ESR` → 接收错误计数 REC 直接到 255 溢出了。
3. 读状态寄存器 `MSR` → RXM=1，说明**总线上其实有信号**，CAN 控制器在努力收。
4. 读接收 FIFO → 挂号数一直是 0，**一帧都没收成功**。

合起来就是：**总线上有信号，但每一帧都收错了**。这是电气层的问题，不是代码问题。

**已经排除的**：波特率（两边都是 1M）、CANH/CANL 接反（对调过没用）、没共地（共了）、电调没上电（灯亮着）、ID 不对（0x201 是对的）。

**还怀疑**：终端电阻。CAN 总线两头要各接一个 120Ω 电阻吸收信号反射，没有的话波形会乱掉全收错。下次断电用万用表量一下 CANH 和 CANL 之间的电阻：60Ω 左右正常，无穷大就是没接终端。

**另外发现**：框架的安全设计是对的——收不到反馈时控制线程会一直把电机关掉（输出恒 0），电机不会乱转。这不是 bug，是故意这么设计的，不能绕过。

## 这次调试学到的

- 调之前先确认烧进去的固件是最新编译的（看 elf 时间戳），不然看到的全是假象。
- 多读芯片的硬件寄存器（错误计数、状态位），比瞎猜强太多。
- 一次只改一个东西，改完测一下记下来，不然不知道是哪步起的作用。
